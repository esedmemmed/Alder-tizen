# Decisions

Format: `## YYYY-MM-DD — title` · What · Why · Alternative considered.

## 2026-10-29 — Rebuild as Tizen web app, AVPlay player
What: Vanilla JS web app (.wgt) for Tizen 5.5 using Samsung AVPlay. Why: Kotlin/ExoPlayer can't run on Tizen; AVPlay is the only player with hardware 4K/HDR on Samsung. Alternative: HTML5 `<video>` + MSE (no MKV, weaker codec coverage).

## 2026-10-29 — DTS/TrueHD avoided, not decoded
What: Streams whose audio is only DTS/TrueHD are excluded from auto-play; multi-audio files get a playable track selected. Why: TU8000 has no DTS/TrueHD decoder or passthrough; software decoding on the TV is unproven. Alternative: TorBox transcoder / home server via the `resolvePlayableUrl` hook (future).

## 2026-10-29 — Dropped: self-update, Watch Next, frame-rate match, passthrough
Why: no Tizen equivalent for a sideloaded app on 2020 firmware. Updates go through Apps2Samsung.

## 2026-10-29 — Phase 2 decisions (accepted in review)
- **Audio key in rank()**: after `awkward`/"may not play" and `fit()`, before Settings' preference; good 3, mixed 2, unknown 1, bad 0. Bad-audio sources never auto-play; listed last with "No sound on this TV". BEST MATCH = first wanted source with sound.
- **"May not play" key**: streams needing request headers other than User-Agent/Cookie rank right after Alder's `awkward` key.
- **Stable sort everywhere** (`util.stableSort`): Chromium 69's Array.sort is not stable; Alder's ranking relies on ties keeping add-on order.
- **Watched bitfield bound**: dropped Alder's extra `bit < ids.size` check; stremio-core's resize bounds by the old bitfield's length only, so Alder could drop the anchor when earlier episodes disappear. Output: zlib level 6, padded base64.
- **bestAudio**: Alder's order (no commentary → language → default flag → channels) with "known playable" as the first key; a commentary-only playable track beats silence; unknown codec strings count as "maybe" and only beat nothing.
- **Subtitle.isLocal** also accepts ISO 639-2/B codes (ger, fre) that OpenSubtitles sends.
- **Kept as Alder**: overallTimeWatched double-count after a video switch (stremio-core parity question, not a Tizen issue).

## 2026-10-29 — Phase 1 decisions
- **Tizen 5.5 engine is Chromium M69; esbuild target `chrome69`.** Samsung's Web Engine Specifications page lists 2019 TVs (Tizen 5.0) at M63, 2020 TVs (Tizen 5.5, TU8000) at M69 and 2021 (6.0) at M76. esbuild lowers syntax only (optional chaining, `??`, class fields, ...), it adds no APIs: `src/lib/compat.js` polyfills what Alder's code needs (`Promise.allSettled/any`, `Object.fromEntries`, `String#replaceAll/matchAll/at`, `Array#at/findLast`, `structuredClone`, `queueMicrotask`, `replaceChildren`, `globalThis`) and `npm run compat` greps `src/` and `dist/app` for APIs and CSS newer than M69 (`gap` on flexbox, `aspect-ratio`, `inset`, `:focus-visible`, `:is()`, `ResizeObserver` use without a guard, ...). Alternative: Babel + core-js (a dependency and a build step for ten small functions).
- **Unstable sort is a compat error.** M69's `Array#sort` is not stable (stable from M70) and Alder's ranking depends on ties keeping add-on order. The rule flags `.sort(` unless the line carries `// compat-ok: unstable sort`; `src/core/util.js` (`stableSort`, Phase 2) is excluded. Waivers are a general mechanism: `// compat-ok: <rule id>`.
- **Design scale is dp x 2, not x 1.5.** PLAN.md section 2 said 1.5. Alder's own 1080p screenshots (docs in the Alder repo) are drawn at 2 px per dp (xhdpi, 960x540 dp), so `tokens.css` takes every dimension from `Screen.kt` times 2 on a fixed 1920x1080 page (`<meta viewport width=1920>`). Colours, radii and type roles are Alder's. **Card focus growth is 1.08** (`Screen.kt CARD_GROW`), PLAN.md said 1.06; Alder's constant wins ("port, don't invent").
- **Fonts are bundled, not downloaded.** Inter (variable) and Instrument Serif, Latin subset, as `.woff` in `src/ui/fonts/` (79 KB + 29 KB), both SIL OFL 1.1 (licence texts shipped in the .wgt under `licenses/`). The TV cannot be assumed to have internet at launch and a web font CDN is not allowed (AGENTS.md). Alternative: system fonts, which on Tizen 5.5 are not Inter.
- **`__ALDER_DEV__` build-time define.** Dev-only code (fixture rewrite in `http.js` / `images.js`, the mock, `window.__alder`) is guarded inline with `typeof __ALDER_DEV__ !== 'undefined' && __ALDER_DEV__`. esbuild folds that to `false` in the production build and drops the branch; a constant imported from another module is not folded, which is why the check is written inline each time. `npm run compat` and `npm run build` fail if `__fx`, `mock-tizen`, `ALDER_FIXTURE` or `sourceMappingURL` reach `dist/app`.
- **Hand-written zip (`scripts/zip.mjs`) for the .wgt.** `node:zlib` plus ~80 lines (stored/deflate entries, fixed timestamp so builds are reproducible, config.xml first). The AGENTS.md dependency list has no zip library and the `zip` CLI is not guaranteed on every machine. `scripts/verify-wgt.mjs` re-reads the result and applies the checks Apps2Samsung's `Packaging/*.cs` makes at install time (no .NET here to run it).
- **.wgt is unsigned, with only public privileges.** Apps2Samsung re-signs it with the user's own certificate. `config.xml`: `<tizen:application id="AldrTizen0.Alder" package="AldrTizen0" required_version="5.5"/>` (attribute order as the tool's regex expects; package id is 10 alphanumerics), privileges `http://tizen.org/privilege/internet`, `http://tizen.org/privilege/tv.inputdevice` and `http://developer.samsung.com/privilege/productinfo` (public level; the productinfo URL was taken from Samsung's API docs and could not be checked against a TV: if Apps2Samsung or the TV rejects it, drop it and read the model name from the user agent). No `on-boot`, no Partner-level privilege (audio/video control would need them: AVPlay does not).
- **Images ask MetaHub for a size that matches the display width** (`images.js sharp(url, widthPx)`: up to 150 px as given, up to 1280 medium, wider large). Alder's `Images.sharp` always asks for the large copy because its TV has the memory; PLAN.md's budget for the TU8000 is "small/medium for cards". Alternative: always large (several times the bytes and decoded memory for 40 cards per row).
- **Kept answers (`Http.saved`) are a size-capped LRU in localStorage keyed by a cyrb53 hash** of method + URL + body, so no URL, add-on address or auth key appears in storage. Alder keeps them in a file; localStorage on Tizen 5.5 survives restarts and gives ~5 MB, so the cache has a byte cap, evicts the least recently used entry and degrades to no caching on quota errors.
- **Rows never use `ResizeObserver`/`gap`/`aspect-ratio`:** card spacing is margins and every card has fixed pixel sizes (the page is a fixed 1920x1080), so none of the post-M69 layout features are needed.
- **The AVPlay mock's `extra_info` shape is a guess.** Samsung documents `getTotalTrackInfo()` as `[{index, type, extra_info}]` with `extra_info` a JSON string but not its field names for every container. The mock produces several spellings (`style`: matroska / mime / fourcc, `indexing`: per-type / global) so the Phase 3 parser is written to tolerate them. First thing to verify on hardware (listed in `dev/README.md`).
- **`java.util.Locale` replacement:** `src/lib/i18n-lang.js` carries a 137-language ISO 639-1/-2 table (English names), enough for add-on subtitle/audio language codes. Languages outside it display as their code, as Alder does for unknown codes.
- **Rows keep Left/Right to themselves and declare Up/Down between rows.** Alder's Home moves between rows by index (`MainActivity.dispatchKeyEvent`) and its rows stop at their ends; a pure FocusFinder-style geometric search does neither once rows scroll and slide: the last card of a scrolled row has other rows' cards "to its right", and mid-slide the top bar can be nearer than the row above (found by running the screenshot scenario at 4-6x CPU throttle). Focus groups take `contain: 'x'` (rows), and stacked rows carry `data-up`/`data-down` pointing at their neighbours (entered through the group handler: same index). Geometry still decides everything else (top bar, panels, buttons).
