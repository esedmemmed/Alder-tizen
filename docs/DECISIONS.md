# Decisions

Format: `## YYYY-MM-DD — title` · What · Why · Alternative considered.

## 2026-10-29 — Rebuild as Tizen web app, AVPlay player
What: Vanilla JS web app (.wgt) for Tizen 5.5 using Samsung AVPlay. Why: Kotlin/ExoPlayer can't run on Tizen; AVPlay is the only player with hardware 4K/HDR on Samsung. Alternative: HTML5 `<video>` + MSE (no MKV, weaker codec coverage).

## 2026-10-29 — DTS/TrueHD avoided, not decoded
What: Streams whose audio is only DTS/TrueHD are excluded from auto-play; multi-audio files get a playable track selected. Why: TU8000 has no DTS/TrueHD decoder or passthrough; software decoding on the TV is unproven. Alternative: TorBox transcoder / home server via the `resolvePlayableUrl` hook (future).

## 2026-10-29 — Dropped: self-update, Watch Next, frame-rate match, passthrough
Why: no Tizen equivalent for a sideloaded app on 2020 firmware. Updates go through Apps2Samsung.

## 2026-10-29 — Phase 2 decisions (accepted in review)
- **Audio key in rank()**: after `awkward`/"may not play" and `fit()`, before Settings' preference; good 3, mixed 2, unknown 1, bad 0. Bad-audio sources never auto-play; listed last with "No sound on this TV". BEST MATCH = first wanted source with sound.
- **"May not play" key**: streams needing request headers other than User-Agent/Cookie rank right after Alder's `awkward` key.
- **Stable sort everywhere** (`util.stableSort`): Chromium 69's Array.sort is not stable; Alder's ranking relies on ties keeping add-on order.
- **Watched bitfield bound**: dropped Alder's extra `bit < ids.size` check; stremio-core's resize bounds by the old bitfield's length only, so Alder could drop the anchor when earlier episodes disappear. Output: zlib level 6, padded base64.
- **bestAudio**: Alder's order (no commentary → language → default flag → channels) with "known playable" as the first key; a commentary-only playable track beats silence; unknown codec strings count as "maybe" and only beat nothing.
- **Subtitle.isLocal** also accepts ISO 639-2/B codes (ger, fre) that OpenSubtitles sends.
- **Kept as Alder**: overallTimeWatched double-count after a video switch (stremio-core parity question, not a Tizen issue).

## 2026-10-29 — Phase 1 decisions
- **Tizen 5.5 engine is Chromium M69; esbuild target `chrome69`.** Samsung's Web Engine Specifications page lists 2019 TVs (Tizen 5.0) at M63, 2020 TVs (Tizen 5.5, TU8000) at M69 and 2021 (6.0) at M76. esbuild lowers syntax only (optional chaining, `??`, class fields, ...), it adds no APIs: `src/lib/compat.js` polyfills what Alder's code needs (`Promise.allSettled/any`, `Object.fromEntries`, `String#replaceAll/matchAll/at`, `Array#at/findLast`, `structuredClone`, `queueMicrotask`, `replaceChildren`, `globalThis`) and `npm run compat` greps `src/` and `dist/app` for APIs and CSS newer than M69 (`gap` on flexbox, `aspect-ratio`, `inset`, `:focus-visible`, `:is()`, `ResizeObserver` use without a guard, ...). Alternative: Babel + core-js (a dependency and a build step for ten small functions).
- **Unstable sort is a compat error.** M69's `Array#sort` is not stable (stable from M70) and Alder's ranking depends on ties keeping add-on order. The rule flags `.sort(` unless the line carries `// compat-ok: unstable sort`; `src/core/util.js` (`stableSort`, Phase 2) is excluded. Waivers are a general mechanism: `// compat-ok: <rule id>`.
- **Design scale is dp x 2, not x 1.5.** PLAN.md section 2 said 1.5. Alder's own 1080p screenshots (docs in the Alder repo) are drawn at 2 px per dp (xhdpi, 960x540 dp), so `tokens.css` takes every dimension from `Screen.kt` times 2 on a fixed 1920x1080 page (`<meta viewport width=1920>`). Colours, radii and type roles are Alder's. **Card focus growth is 1.08** (`Screen.kt CARD_GROW`), PLAN.md said 1.06; Alder's constant wins ("port, don't invent").
- **Fonts are bundled, not downloaded.** Inter (variable) and Instrument Serif, Latin subset, as `.woff` in `src/ui/fonts/` (79 KB + 29 KB), both SIL OFL 1.1 (licence texts shipped in the .wgt under `licenses/`). The TV cannot be assumed to have internet at launch and a web font CDN is not allowed (AGENTS.md). Alternative: system fonts, which on Tizen 5.5 are not Inter.
- **`__ALDER_DEV__` build-time define.** Dev-only code (fixture rewrite in `http.js` / `images.js`, the mock, `window.__alder`) is guarded inline with `typeof __ALDER_DEV__ !== 'undefined' && __ALDER_DEV__`. esbuild folds that to `false` in the production build and drops the branch; a constant imported from another module is not folded, which is why the check is written inline each time. `npm run compat` and `npm run build` fail if `__fx`, `mock-tizen`, `ALDER_FIXTURE` or `sourceMappingURL` reach `dist/app`.
- **Hand-written zip (`scripts/zip.mjs`) for the .wgt.** `node:zlib` plus ~80 lines (stored/deflate entries, fixed timestamp so builds are reproducible, config.xml first). The AGENTS.md dependency list has no zip library and the `zip` CLI is not guaranteed on every machine. `scripts/verify-wgt.mjs` re-reads the result and applies the checks Apps2Samsung's `Packaging/*.cs` makes at install time (no .NET here to run it).
- **.wgt is unsigned, with only public privileges.** Apps2Samsung re-signs it with the user's own certificate. `config.xml`: `<tizen:application id="AldrTizen0.Alder" package="AldrTizen0" required_version="5.5"/>` (attribute order as the tool's regex expects; package id is 10 alphanumerics), privileges `http://tizen.org/privilege/internet`, `http://tizen.org/privilege/tv.inputdevice` and `http://developer.samsung.com/privilege/productinfo` (public level; the productinfo URL was taken from Samsung's API docs and could not be checked against a TV: if Apps2Samsung or the TV rejects it, drop it and read the model name from the user agent). No `on-boot`, no Partner-level privilege (audio/video control would need them: AVPlay does not).
- **Images ask MetaHub for a size that matches the display width** (`images.js sharp(url, widthPx)`: up to 150 px as given, up to 1280 medium, wider large). Alder's `Images.sharp` always asks for the large copy because its TV has the memory; PLAN.md's budget for the TU8000 is "small/medium for cards". Alternative: always large (several times the bytes and decoded memory for 40 cards per row).
- **Kept answers (`Http.saved`) are a size-capped LRU in localStorage keyed by a cyrb53 hash** of method + URL + body, so no URL, add-on address or auth key appears in storage. Alder keeps them in a file; localStorage on Tizen 5.5 survives restarts and gives ~5 MB, so the cache has a byte cap, evicts the least recently used entry and degrades to no caching on quota errors.
- **Rows never use `ResizeObserver`/`gap`/`aspect-ratio`:** card spacing is margins and every card has fixed pixel sizes (the page is a fixed 1920x1080), so none of the post-M69 layout features are needed.
- **The AVPlay mock's `extra_info` shape is a guess.** Samsung documents `getTotalTrackInfo()` as `[{index, type, extra_info}]` with `extra_info` a JSON string but not its field names for every container. The mock produces several spellings (`style`: matroska / mime / fourcc, `indexing`: per-type / global) so the Phase 3 parser is written to tolerate them. First thing to verify on hardware (listed in `dev/README.md`).
- **`java.util.Locale` replacement:** `src/lib/i18n-lang.js` carries a 137-language ISO 639-1/-2 table (English names), enough for add-on subtitle/audio language codes. Languages outside it display as their code, as Alder does for unknown codes.
- **Rows keep Left/Right to themselves and declare Up/Down between rows.** Alder's Home moves between rows by index (`MainActivity.dispatchKeyEvent`) and its rows stop at their ends; a pure FocusFinder-style geometric search does neither once rows scroll and slide: the last card of a scrolled row has other rows' cards "to its right", and mid-slide the top bar can be nearer than the row above (found by running the screenshot scenario at 4-6x CPU throttle). Focus groups take `contain: 'x'` (rows), and stacked rows carry `data-up`/`data-down` pointing at their neighbours (entered through the group handler: same index). Geometry still decides everything else (top bar, panels, buttons).

## 2026-10-29 — Phase 3 decisions (player)
- **AVPlay sequence and picture area.** `open` → `setListener` → `setDisplayRect(0,0,1920,1080)` → `setDisplayMethod(LETTER_BOX)` → `setStreamingProperty` → `prepareAsync` → track decision (`setSelectTrack`) → resume seek → `play`. Samsung says AVPlay's coordinates are always 1920x1080, and the page is a fixed 1920x1080, so the rect never needs scaling. LETTER_BOX is ExoPlayer's "fit, never crop". An `<object type="application/avplayer">` is put in the player screen. The picture is on a plane behind the page, so the production build makes `html`/`body` transparent while the player is up (`html.av-live`); the dev build keeps the dark background (headless Chromium has no plane and would paint white) and hides the object (it prints "Couldn't load plugin"). Alternative: opaque page with a punched hole (not documented for AVPlay).
- **"A picture is showing" is playback time advancing after `play()` (revised after review).** ExoPlayer's `onRenderedFirstFrame` has no AVPlay twin, and `onbufferingcomplete` is not a substitute: AVPlay can buffer happily while the decoder never renders (unsupported profile, Dolby Vision P5, a broken file), and treating that as a picture would stop the failover and save progress for a source that never played. The engine now counts a picture when `oncurrentplaytime`, after `play()` was called, reaches `startAt + 500 ms` or reports two increasing times in a row. `onbufferingcomplete` only hides the loading overlay; START_WAIT (12 s) keeps running until the time signal, then moves to the next source. Nothing is saved, remembered or pushed before it. Alternative (first version): buffering complete or time past 250 ms. To confirm on the TU8000 (the log shows each event).
- **Top-left name chain** (controls): the title's logo picture, else its name (params, then the meta's), else nothing; a bare IMDb id is never shown as a name. Long names ellipsize.
- **Add-on subtitle files are drawn by us.** Alder hands the URL to ExoPlayer and, for a timing shift, rewrites the file. AVPlay can only be given a local/HTTP SMI-or-SRT path with its own limits and no restyling, so the file is fetched through `lib/http`, parsed (SRT, VTT, ASS) and drawn in a div synced to AVPlay's time; Settings' size (`TEXT_SIZE_FRACTION` of the height) and background apply, a shift is an offset (no reload, no new fetch). The file's own text tracks use `setSelectTrack('TEXT')` + `onsubtitlechange`, drawn by the same overlay. Alternative: `setExternalSubtitlePath` (kept as the fallback to try if drawing proves too slow on the TV).
- **Start subtitle rule is Alder's** (only the TV's language, ignore forced/default flags). The TV's language is Settings' audio language, else `tizen.systeminfo` LOCALE, else `navigator.language`, as two letters. `tizen.systeminfo` may need a privilege `config.xml` does not declare; until then the code falls back to `navigator.language` (Tizen sets it to the menu language) and the log says which one answered. See Requests.
- **Retries and error names.** Alder retries ExoPlayer's 2000..2999 network errors except HTTP 4xx (other than 408 and 429). AVPlay's only network error is `PLAYER_ERROR_CONNECTION_FAILED`; it is retried (2 times, 1.5 s apart, fresh START_WAIT each), and an HTTP status from `PLAYER_MSG_HTTP_ERROR_CODE` (its data format is not documented: the engine reads a 3-digit number out of it) turns a 4xx into a failed source. Every other error (`NOT_SUPPORTED_FILE`, `INVALID_URI`, `NO_SUCH_FILE`, ...) fails the source at once. `PLAYER_ERROR_NOT_SUPPORTED_FORMAT` is treated as a decoder error and tries the next audio track first (Alder's `rendererFormat` check). `SEEK_FAILED` is not a source failure.
- **Request headers.** AVPlay's `setStreamingProperty` knows `USER_AGENT` and `COOKIE`; any other header (Referer, Authorization, ...) is logged as unsupported and the stream is tried anyway (Phase 2 already ranks those streams lower).
- **`extra_info` and `getTotalTrackInfo` doubts.** Samsung documents no field names; `parseAudioTracks`/`parseTextTracks` read several spellings. Forum reports say a real audio entry looks like `{"language":"ENG","channels":"2","sample_rate":"48000","bitrate":"0","fourCC":"audio/mpeg"}` (MIME-like fourCC, now classified: `audio/mpeg` is MP3, `audio/mp4a-latm` AAC), and that on Tizen 5.5 DASH may answer `"notSet"` (read as an empty list: AVPlay's own audio choice stands). Diagnostics prints the raw list so the first TV test settles it.
- **Audio the TV cannot decode stays in the panel**, greyed with "No sound on this TV", and OK on it only shows that message (Alder lists only supported tracks; here support is a guess about a model, so hiding the track would hide the reason).
- **The player has its own focus.** It takes every key (as `dispatchKeyEvent` does) and marks the focused control with a class, rather than using the shell's focus engine. OK held 600 ms counts as OK (the dispatcher sends one press or one hold per OK, so Alder's wake-key bookkeeping is not needed). Back closes the card, then the options, then the controls, then leaves the player (saving). The Stop key also leaves. Left/Right on the bar step 10 s, then 30 s and 60 s while held (Alder's repeat thresholds).
- **No buffered stretch on the bar.** AVPlay reports only a buffering percentage during stalls, not a buffered position, so the lighter "buffered" stretch of Alder's SeekBar equals the playing point.
- **Near-opaque panels.** The options panel is 94% opaque (Alder: 0xF0) and the cards 88%: video cannot be frosted and `backdrop-filter` is not available on Chromium 69.
- **The Skip intro pill steps aside for a card** (Up next, stall) that occupies the same corner; Alder let them overlap.

## 2026-10-29 — Phase 4B decisions (title page, sources, search, settings, add-ons)
- **Screens read `context.session` only** (docs/CONTEXT.md); nothing here opens a store key or an HTTP call itself, except that Add by URL fetches the manifest through `session.http`. Pure logic ported from the Kotlin top-level functions lives in `src/ui/screens-b/helpers.js` (no DOM, tested in `test/screens-b/`); DOM helpers shared by the five screens are in `kit.js`. All styles are in `src/ui/screens-b/screens-b.css`, imported from `main.css` (one added line in a shared file). Class prefixes are `b-`, `dt-`, `eg-` (episode guide), `st-`, `sr-`, `sg-`, `ad-`; `dg-` is Diagnostics' and an early collision with it was renamed.
- **Panels are 93% opaque, the art is not blurred.** Alder frosts the picture behind the sources, settings and add-ons panels with a blur; `backdrop-filter` is not available on Chromium 69 and blurring a full-screen picture in JS or with `filter` costs a repaint the TU8000 cannot afford. The picture behind is darkened and the panel is near opaque (as in Phase 3's options panel).
- **Search: no voice key; a real `<input>` behind the grid.** The voice key has no Tizen twin, so SPACE takes its row. The letter grid types into an `<input>` (so the TV's own keyboard/IME can type too, `Done` is keyCode 65376) and a drawn cursor stands in for the caret while the focus is on the grid. Search runs 500 ms after typing stops, across the account's add-ons, each within 5 s (`Addon.search`), settling after 6 s with what has answered.
- **Settings is Alder's, minus what a Tizen TV cannot do, plus three rows.** Dropped: frame-rate matching, audio passthrough and the updates row (AVPlay chooses output, there is no self-update). Added: Advanced "My TV plays AV1" toggle (off by default: the TU8000 has no AV1 decoder, 2021+ models have), a Diagnostics row in About (hold OK on the version works too, as in Phase 3), and "Based on Alder" (GPL-3.0 credit). Left/Right on a value row step it, Left on any other row and Back go to the group list, Back from the group list leaves.
- **Storage "Clear local storage"** calls `store.clear()` and reloads the page (Alder clears its files and restarts the activity).
- **Group icons Profile / Language / Storage are inline SVG**, not the glyph characters Alder draws (♙ ◎ ▤): the bundled Inter and Instrument Serif subsets lack them and a fallback font would be a different weight on a TV.
- **Sources: `picked` plays with `push`, auto-start with `replace`.** Play (no list asked for) finds sources and, when the Play rule says best source, replaces the sources page with the player so Back goes to the title page. A source chosen from the list is pushed on top, so Back returns to the list (Alder's `startActivityForResult`). The player gets the first `TRY` (3) ranked playable sources, or just the chosen one with `picked: true`. The player's own `navigate` events (`sources`, `next`) are wired by the shell.
- **Rows for sources the TV cannot use are dimmed to 62% until focused**: "No sound on this TV" (DTS, TrueHD and friends, the TU8000 has neither), and "May not play" (needs request headers AVPlay cannot send). They stay listed, last, so the reason is visible (Phase 3 does the same in the audio panel).
- **The title page's episode guide is a second layer, not a new page.** Down from the buttons opens it over the same screen (Back closes it, hold OK on an episode lists its sources with `pick: true`, plain OK plays, Up from the first rows goes to the season chips). "More like this" for a movie is the same: only when an add-on offers a `similar` catalogue.
- **Fixtures added (add-only):** `subs.fixture.test/sev104/*.srt` and `sev105/eng-1.srt` (named by the OpenSubtitles fixtures; REVIEW-phase3 carry-over), Cinemeta meta for `tt1160419` (Dune, 2021) and `tt0142032` (Frank Herbert's Dune) so the search results open, and empty Watchly stream answers for Severance 1:4 and 1:5 (an add-on with no streams answers `{"streams":[]}`; the harness treats a 404 as a console error).

## 2026-10-29 — Phase 4A decisions (session, sign-in, profiles, Home)
- **`src/app/session.js` is the one place the app's services are assembled** (`context.session`): profiles, settings (a shared object that reads the active profile), add-ons (the parsed list is memoised until the collection changes), the Stremio client, `library()`/`books` (the core `Library`, which the player also gets as `context.player.library`), the source memory, the device profile (`device.av1` is a live getter, so the Settings toggle takes effect without a restart), a `coreHttp` adapter between `lib/http` and the core's `{get, post}` shape, and `finder()`, which returns an unstarted `SourceFinder` for the sources page to run. Screens never open a store key or an HTTP call themselves.
- **Sign-in also offers e-mail and password.** Alder has only the link code (QR). A TV with no phone nearby had no way in, so "Sign in with e-mail instead" is on the code page (the on-screen keyboard types it; `Stremio.login`). Alternative: link code only, as Alder.
- **Panels are near-opaque (`--pane`, 94%) and nothing uses `backdrop-filter`** (REVIEW-phase1 carry-over). The picker's backdrop is one film's art copied to a 64 x 36 canvas and stretched (as soft as Alder's frost, with no `filter: blur`), over Alder's own night scene (`onboarding_scene.webp`, 216 KB, copied from Alder's `drawable-nodpi`; `scripts/build.mjs` gained a `.webp` file loader for it). Sign-in steps show the scene alone at 35%, the picker at 42%.
- **The PIN is Alder's four boxes, not a pad.** Up and Down turn the digit in the box, Left and Right move (Right only once the box has a digit), number keys type and move on, OK or the fourth digit submits; the same wording ("Incorrect PIN. Try again.", "PINs don't match. Try again."). An early version here drew a 0-9 pad; Alder has none, and the TV remote has number keys.
- **Share my streaming sources stays in Settings** (4B's `settings.js`), where Alder keeps it (`SettingsActivity`); the profile menus (hold OK on a portrait) do not carry it, as in Alder.
- **`src/ui/row.js` (shared) grew**: `slide` mode (the row's selected card stays where Alder's `slideFor` puts it, with `safeRight`), `append(extra)` for paging, `viewportTop`/`className` options, getters `step`, `padLeft`, `length`, and right-to-left mounting so the cards nearest the focus exist first. `slideFor` is exported and tested (`test/lib/row.test.js`). Rows are built lazily on Home: only the row in use and the ones next to it exist, which keeps card nodes well under the 150 budget (4 to 24 in the scenarios).
- **The art layer has no 20 s zoom and no "bright edge" sampling.** Alder pans the art slowly and measures the left edge to strengthen the shade; both cost per-frame or per-image work (a canvas read-back) that a TU8000 does not need. The shades are CSS gradients, always at Alder's strongest setting (`.art-shade`). Image changes cross-fade with opacity only (600 ms).
- **Not ported from Home:** the cinema screensaver and idle dim (Alder ships them off), Watch Next channel (Tizen has no twin), the in-app update offer (no self-update on Tizen). Hold OK on Continue opens the sources list with `pick: true`, as in Alder; OK opens the title page.
- **The caption is hidden while the remote is in the top bar, even when the hero shows a title there** (Alder's focus listener hides it, but `showHero` can show it again after the page loads while the remote is still up there; here `showHero` hides it again).
- **My List's grid does its own focus** (`gridKey`): six across, a row at a time, rows r-1..r+2 mounted, rather than the geometric search, because a scrolled grid has other rows' cards "to the right". Left/Right wrap nowhere; Up from the first row reaches the chips, then the top bar.
- **Player `onNavigate` (`src/app/navigation.js`)**: `exit` pops; `sources` replaces the player with the sources page (or pops the sources page under it first, so the stack never holds two); `next` goes through the sources page for the next episode (`pick: false`, `nextVideoId` the one after), which starts it without a list, as Alder's "Up next" does; `details` returns to the title page below, or replaces the player with one.
- **First screen** (`firstScreen`): no profile is sign-in; several profiles, or one with a PIN, the picker; one plain profile goes straight to Home. In dev builds `?profile=fixture` adds the fixture profile so scenarios can start at Home (the code is behind `__ALDER_DEV__` and absent from `dist/app`).
- **Fixtures added:** genre catalogs for Cinemeta (Drama, Comedy, Crime, Sci-Fi, Action; Documentary is empty so its chip stays hidden), empty `skip=N` pages for every catalog fixture that Home pages through (a 404 fails the harness), `watchly.item.tt0816692` ("Because you watched Interstellar", a Home row) in Watchly's manifest and in the fixture add-on collection. The old Phase 1 and Phase 3 scenarios now run on the real Home with `?profile=fixture`.

## 2026-10-29 — Picture size: Fit is LETTER_BOX; Fill is built but not offered (v0.2)
Question: on the owner's TU8000 some films "didn't fill the whole screen". Is it the source (2.39:1 bars in the file) or the player, and can the player fill the screen without stretching?

**What Samsung documents** (AVPlay API reference, read 2026-10-29; the pages are truncated for the fetcher, so "not documented" means "not in the text we could read"):
- `setDisplayMethod(AVPlayDisplayMode)`: three values, `PLAYER_DISPLAY_MODE_LETTER_BOX` ("letterbox mode"), `PLAYER_DISPLAY_MODE_FULL_SCREEN` ("full-screen mode") and `PLAYER_DISPLAY_MODE_AUTO_ASPECT_RATIO` ("screen mode based on video dar/par info"). No "since" and no remarks. **There is no cropping mode**: `CROPPED_FULL`, `ORIGIN_SIZE` and `DST_ROI` exist only in the native C API (`player_display_mode_e`, docs.tizen.org), not in AVPlay. The AVPlayExtension page adds that "this API works when set as setDisplayRect(0,0,1920,1080)": the display method is only specified for the full-screen rect.
- `setDisplayRect(x, y, w, h)`: `unsigned long` arguments in a 1920x1080 coordinate system, "x smaller than the TV screen width", "y smaller than the TV screen height", throws InvalidValuesError for invalid values. Behaviour beyond the screen is not documented. Unsigned means no negative offsets, so a rect larger than the screen cannot be centred (it could only hang off the right and bottom, cropping one side only).
- `setVideoRoi(double x_ratio, double y_ratio, double w_ratio, double h_ratio)`: listed in the AVPlayManager interface, with **no description, no "since" and no remarks**; it is not mentioned in Samsung's "Playback Using AVPlay" guide, and nothing says it works on a 2020 TV (or what the ratios are of).
- `getVideoSize()` returns `{width, height}` ("from demux side", "for TV supported for local content only", since 10.0): useless for streams. The video track's `extra_info` ("JSON string containing all media-related info") is documented to carry "height, width and fourCC for a video stream"; no aspect or pixel-aspect field is mentioned.

**Decisions**
1. **Fit = `PLAYER_DISPLAY_MODE_LETTER_BOX`, unchanged.** AUTO_ASPECT_RATIO sounds right for anamorphic files (it reads dar/par), but nothing documents what it does for a file with neither (a stretch to full screen would be the worst case), no TV test has been done, and LETTER_BOX is what 0.1.0 ran on the owner's TV: the films that "did not fill" were showing their bars, not a wrong shape. Square-pixel files, nearly every release, look the same either way. The method is one constant (`FIT_METHOD` in `src/player/avplay.js`); trying AUTO_ASPECT_RATIO on the TV is one line (TV-TEST request below). Alternative: AUTO_ASPECT_RATIO now.
2. **Never FULL_SCREEN**: it stretches to the screen's shape, which is exactly what "Fill" must not be.
3. **Fill is built (a crop through `setVideoRoi`, then LETTER_BOX fits what is left: never a stretch) but not offered in the shipped build** (`FILL_ENABLED = false`). It is the only API that can crop and Samsung gives its signature and nothing else, so whether it works on a TU8000 is unknown, and a feature that may silently do nothing, or something else, on the owner's TV should not be a menu item. The rect route is impossible (above). With the flag off the player has no Picture row, Settings has no Picture size row (a choice of one is not a choice), and everything else is live: the source's shape text and the "black bars are part of the film" note in Info, in the Audio & subtitles panel's Picture section when offered, and in Diagnostics. The dev build offers Fill with `?fill=1` so the panel, the Settings row, the per-profile default and the mock are tested. To ship Fill after the TV test: set `FILL_ENABLED = true`.
4. **Fill's geometry** (`picture.js fillRoi`): the largest part of the frame with the screen's shape, centred, as ratios of the frame: 2.40:1 keeps the middle 74% of the width (26% cut off), 4:3 keeps the middle 75% of the height. For anamorphic files the shape is the display shape (`display_aspect_ratio`, or stored shape times `pixel_aspect_ratio`), so the crop is right for non-square pixels. A 16:9 file has nothing to cut and no call is made. If the TV throws, the picture stays Fit and the panel/Info/Diagnostics say "the TV refused the crop".
5. **The source's shape is read from the VIDEO track's `extra_info`** (`parseVideoShape`): Width and Height under several spellings (`Width`, `width`, `video_width`, ...; the lenient `parseExtraInfo` reader copes with non-JSON), plus display or pixel aspect under several names when a TV reports them (a guess, like the audio fields: Diagnostics prints the raw track list, so the first TV run settles it). Shown as "1920×800 · 2.40:1" with "This film is wider than your TV (16:9), so the black bars above and below are part of the film." when the shape is more than 4% wider than 16:9 (1.85:1 gets no note), and the mirror sentence for taller video. If the TV reports no size, the text says "this file doesn't say its size" and nothing is claimed.
6. **Info is a card now.** The player's Info button used to open the title page at once (Alder). It now opens a card with the picture's shape, what is showing (Fit/Fill) and the source, with "Title page" one press further, because the owner's question when a film "doesn't fill the screen" is whether the bars are in the file. Alternative: add the shape to the paused screen only (it is not shown while playing).
7. **Remembering**: Fit/Fill is a per-profile default (`settings/pictureSize@<profile>`, Settings → Picture & Sound → Picture size), and a choice made in the panel while watching is saved as that default (applied at once, same second, no reload and no seek). Removed with the profile.
8. **Re-applied** after prepare (before `play()`), after a suspend/restore, and for each new source on failover (a new session starts with the whole frame). ## 2026-10-29 — v0.2 focus: focused items are filled, not rimmed (deviation from Alder)
- **What.** Alder marks focus with a tungsten rim, a glow and a lift (and a faint `ROW_FOCUSED` tint on list rows). On the TU8000 from a sofa the owner could not follow it, so every focusable thing except a poster card now takes **one solid warm-white fill with dark ink** (`--focus-fill` #F2E8D8, `--focus-ink` #15110E): top-bar tabs, chips, round icon buttons and the profile avatar, list rows (Settings sidebar and rows, Sources, Audio & subtitles, menus, add-ons, episode guide), keyboard keys and the PIN box the remote is on. Primary pills (Play/Resume, Up next) were already filled: they grow to 1.06 and get a ring and a stronger glow. Round buttons grow to 1.10 and show their name under them (drawn from `aria-label` with `::after`, no extra markup). Cards keep Alder's rim and 1.08. Idle chips are outline only, selected chips a translucent fill plus Alder's dot, idle round buttons dark glass (`--glass-dark`); "current" rows, tabs and chips keep a translucent fill / tick / dot so *current* and *focused* never look alike. Tokens: `--focus-*`, `--sel-fill`, `--chip-edge`, `--glass-dark`, `--btn-grow`, `--pill-grow`, `--t-fill`, `--t-slide`.
- **How it stays within the TU8000 budget.** Only `transform` and `opacity` ever transition (120-180 ms): the fill is a `::before` layer behind the content (`z-index: -1` in the element's own stacking context) faded in by opacity; the rings are `::after` layers faded the same way. The top-bar highlight is **one** element (`src/ui/navhl.js`) that slides under the focused tab: a container moved by `translateX`, a left and a right round cap, and a 1 px middle scaled in X (a single scaled pill would squash its round ends). Tab positions are measured with `offsetLeft`/`offsetWidth` on focus; the current tab's bolder label is drawn with a text stroke so its width does not change and one measure stays true. It is a delegated `focusin` handler (installed by importing the module from Home and from the Search screen's `kit.js`), so no screen needs wiring. Text colour switches at once on focus (a colour transition is not transform/opacity); the fill fades under it in 140 ms.
- **Contrast.** Inside a focused item the colour variables are re-declared (`--text` and `--text-2/3` become the two inks, `--tungsten` becomes a dark amber `--focus-accent` #5C3D0E, `--base` the fill, `--glass-edge` a dark hairline), so every secondary text, tag, badge, tick, switch track and "THIS PROFILE" label written with those variables is readable with no per-screen rule: ink 15.5:1, secondary ink 8.3:1, accent 8.1:1 against the fill (all >= 7:1). `dev/scenarios/v02-focus.mjs` reads the computed colours of every text and icon in each focused state and fails below 7:1; it also fails on any transition that is not transform/opacity at 100-200 ms. Dimmed rows (a source with "No sound on this TV", an unplayable audio track) go to full opacity while focused, since faded ink on the fill would not pass.
- **Not changed.** `src/lib/focus.js` and row virtualisation (nothing here touches focus handling; a focus move is still `el.focus()` plus class-free CSS). The player's controls keep their own `.focus` class (the new rules are written for both `:focus` and `.focus`).
- **Alternative considered.** Animating `background-color`/`box-shadow` (simple, but repaints, and the plan bans it for this CPU); one scaled-X pill for the nav (distorts the round ends); a per-screen palette for each row type (the variable scope does it once).
